# Proposed document classification extension DC1

Requested by the user on teguh: select multiple PDFs once and classify their content into the existing nine DocumentType values. PDF is the only accepted format. This new request authorizes frontend changes for that workflow, superseding the preceding P1 prompt's frontend restriction for this task only. Existing P1 work remains intact.

Status: **PROPOSED / opt-in local pilot**. No P0 route/request/response or enum is renamed. Existing single-file multipart upload (initial type OTHER) and expected_version document PATCH remain unchanged. Classification has a separate flag PROCUREMIND_DOCUMENT_CLASSIFICATION_ENABLED (default false); the browser opts in with VITE_DOCUMENT_CLASSIFICATION_ENABLED=true. The local pilot is requested by the user; shared deployment needs review of this addendum.

POST /api/v1/documents/{document_id}/classifications returns 201 with the canonical envelope. Requires document:write, case membership, Idempotency-Key and {expected_version: positive integer}. Unknown fields are rejected. Response: document_id, case_id, expected_version, suggested_type (existing DocumentType), confidence (0..1), status (AUTO_READY/NEEDS_REVIEW), rationale, evidence (existing page-addressed citation shape), ai_execution_id. This command proposes a type; it never edits the PDF or document metadata. Browser applies AUTO_READY through the existing versioned document PATCH. Low confidence, unknown type, conflicting heading signals or invalid excerpts never cause automatic assignment. OTHER always requires manual confirmation.

The real schema-constrained provider reads bounded authorized PDF page text. Filename is excluded from AI input to avoid misleading filename bias. Prompt definitions distinguish governing TOR vs detailed specification, buyer cost estimate vs supplier quotation, justification vs evaluation, signed contractual obligations vs warranty evidence. Confidence alone is never sufficient: an exact verified page-one heading and independently recognized primary document role are required for AUTO_READY. Prompt-injection instructions in PDFs are untrusted. No accuracy percentage or certainty guarantee is made; preview and manual correction remain available for every file.

The existing immutable AiExecution records capture actual model/usage or null, operation DOCUMENT_CLASSIFICATION, prompt_version document-classification-v1, latency and excerpt checks/warnings. Existing GenerationLease prevents same-key in-flight provider duplication; requests are replayed from existing IdempotencyRecord. Both successful proposals and controlled AI failures persist delegated audit/provenance in a caller transaction. Recheck ACL and expected_version after inference; source mutation/revocation prevents applying an obsolete proposal. No new tables or migration are required beyond P0 0002.

Batch UI retains uploaded documents if classification fails, retries classification without uploading them again, and keeps the prepared request on transport uncertainty. Classification errors are distinct from upload failures. Classification and type PATCH run at most two files concurrently; an individual failure does not discard other uploaded PDFs. Human corrections use the existing type editor. No classification implies substantive compliance, authentic signature or procurement approval.
