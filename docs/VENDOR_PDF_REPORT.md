# Vendor comparison PDF export

Assure's vendor comparison can be exported as an actual PDF file using the current comparison snapshot. `createVendorComparisonPdf(comparison, fontBase64, generatedAt?)` returns a jsPDF document; the parent UI supplies the bundled Noto Sans font and triggers the direct download. The generator makes no network requests and does not access browser storage, the DOM or backend mutation endpoints.

The report records the case and job IDs, actual processing/business statuses, generated time in Asia/Jakarta and UTC, the current vendor preference and whether it is provisional, documentation finding scores, per-vendor package coverage and source document inventory, loaded workflow counts, finding details and exact cited passages, resource IDs and contract limits. It exports only the data present in the comparison snapshot. Its vendor document inventory is not represented as a complete inventory of every case document.

When the snapshot includes recorded experimental finding scenarios, the PDF adds their current situation, assumptions, alternatives and possible effects, limitations, deterministic check statuses/descriptions/observations, remaining uncertainties, source citations and actual AI execution provenance. Provider/model, prompt version, schema/evidence validation, counters, measured latency and reported token usage come from each saved execution. These scenario drafts are clearly separated from deterministic checks and are not represented as guaranteed outcomes or resolved findings. Additional loaded progress measures and record-reference IDs, including finding scenarios, are included when present.

Scores preserve the current finding-count rubric: GREEN is zero active applicable findings with completed coverage, YELLOW is one or two, and RED is three or more. Incomplete coverage remains unscored. Shared points contribute to the affected vendors but remain the same finding IDs. Vendor preference does not approve procurement, resolve findings or update assurance state. G01 and incomplete simulation-method coverage stay visible.

The PDF uses A4 pages, repeated headers, page numbers, wrapped text and document hashes, continuing table rows, and source evidence sections. Noto Sans Regular is embedded rather than relying on a viewer's local fonts. The bundled font's license remains alongside it in `frontend/public/fonts/OFL.txt`. If an input character has no glyph in that font, it is visibly preserved as a Unicode code-point label such as `[U+1F600]` with a report note; source text is not silently dropped. Unsupported glyph notation is display formatting and does not change the source comparison object.

The PDF is a static review artifact. It does not certify full vendor compliance, complete workflow execution, audit-chain integrity or an award decision. It contains no live external links, executable PDF actions or remote resources.

Regression cases are authored in `frontend/tests/vendor-pdf.test.mjs` for an actual PDF signature and embedded font, source immutability, long multi-page content, Unicode/missing glyph handling, empty comparisons and explicit font/timestamp errors. At the user's instruction to implement the revision without testing, these new cases have not been executed and the new PDF layout has not been rendered or visually validated. Validation remains pending.
